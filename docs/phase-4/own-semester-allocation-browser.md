# Student saved semester simulations

The protected Planner includes an independent own-history panel for the current account.
It reads at most five historical outcomes, opens older pages using their exact confirmed
boundary, and verifies a selected result against its complete immutable history receipt.
Each data read uses the validated cookie-account adapters. There is no POST, polling,
focus-triggered history read, browser journal or academic/resource change in this panel.

Pending and failed reads hide all prior page/result evidence. Private refs retain only the
exact request needed for explicit retry. Runtime schemas reject private fields, inconsistent
credit math, boundary violations and changed selected receipts even when adapters are mocked.
Owner-keyed remounts and generation/cleanup guards discard stale successes, failures and saved
handlers. An observed wrong/invalid owner or preflight 401/403 in the surrounding Planner
also unmounts historical evidence. Successful same-owner Planner refresh permits a fresh
history read. Same-owner curriculum/intensity changes and unrelated planner source/transport
failures preserve this independent panel; its next operation always checks the account again.

The screen reports the captured simulation budget, assigned/remaining credits, scenario,
stored times and a plain stop reason. It does not reinterpret old results using current
course names or curriculum membership. Frozen V1 did not capture names, so the screen says
so and shows stored course identifiers/credits. Credit budgets are reference settings, not
actual registration requests or proof of eligibility, allocation or timetable validity.
Older scopes remain visible to their live participant account regardless of its current role.

Empty initial and older pages have distinct wording. Completion uses a live announcement;
confirmed selected reads focus their result heading. Browser fixture checks cover desktop,
normal app size and 390px phone width, 44px controls, wrapped identifiers, no horizontal
overflow, older-page replacement and failed selected-read hiding followed by explicit recovery.
The fixtures never call the live application database or perform academic writes.

Thirty focused panel cases and ten Planner integration cases cover privacy/account transitions,
exact retries, frozen receipts, stale handlers, strict schemas, account expiry, keyboard focus,
blocked in-flight responses and independent current-planner behavior. Required full gates and
the next separate semester job increment are recorded in AGENTS.md. Existing one-course jobs
and frozen V1 storage remain unchanged. Full-scale profiling and verified curriculum,
category/grade-fit, calendar, staff/lab and deployment gates remain open.
