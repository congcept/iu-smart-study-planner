# Explicit semester simulation request controls

The ADMIN resources screen mounts one small semester request panel after a confirmed
owner/scenario resource-reference load. It shows this tab's latest request, with explicit
queue, same-key queue retry, exact outcome check and selected-job execution. Requests use
saved resource inputs, excluding unsaved form edits. There is no request history browser,
automatic write, execution, polling, focus refresh or extra saved-capture lookup.

The panel publishes the immutable receipt and current outcome together only after strict
confirmation. All evidence is hidden during pending or failed checks. Private refs preserve
exact original requests, receipts and terminal outcomes for explicit recovery. Owner/scenario
remounts, generation/busy guards and render-intent checks reject stale replies, hooks and
same-mounted handlers. Scope casing and resource revisions do not create a new request.

Writes use the adapter's synchronous final-confirmation hook after fresh cookie ADMIN
preflight immediately before POST, checking generation and exact journal bytes. Lost enqueue
responses retain the same durable key. Physically saved receipts after uncertain readback
can be explicitly recovered only for the same pending request. Execution keeps the selected
job ID; lost replies require read-only original outcome recovery before another explicit
execution. Replacing a request requires fresh exact receipt/outcome reads confirming terminal
state, then conditional journal replacement. Known receipts and terminal results cannot change.

Parent-confirmed wrong, malformed or expired administrator identity unmounts the panel,
including resource-save preflight and confirmation failures. Fresh same-owner ADMIN
verification permits a new mount. Generic preflight transport failures preserve independently
confirmed child state and dirty resource fields. Resource recovery and all existing one-course
and direct-capture flows remain separate.

Copy uses plain queue/completion/failure meanings and explicit simulation limits. Identifiers
wrap, buttons retain 44px minimum height, and status/alert announcements and semantic times
support recovery. Keyboard completion uses live status announcements; explicit result focus
is a possible later improvement. Successful execution saves simulated student outcomes;
participants can review their own result in Planner. Academic records remain unchanged.

Verified tests, desktop/mobile fixture observations and next direction are in AGENTS.md.
Fixture browser checks do not execute live database jobs. Verified curriculum, category/grade
fit, timetable/calendar/staff/lab and maximum-semester-workload gates remain open.
